# lineagelens

**Find the AI-written code already in your repo.**

```bash
npx lineagelens scan .
```

No install, no backend, no account, no API key. Read-only — it runs `git log` and
`git blame` and writes nothing.


## Why this exists

`git blame` tells you which *person* last touched a line. It cannot tell you that
the line was generated by an agent from the prompt "add rate limiting to
/api/login".

Every tool that answers that question needs to be installed *before* the code was
written. So on day one, a repo with a year of AI-assisted commits in it tells you
nothing — which is exactly the code you most need to account for.

`scan` reads that history out of git instead. AI coding tools already sign their
own work: `Co-Authored-By: Claude`, `copilot-swe-agent[bot]`, `aider:` subjects,
`devin-ai-integration[bot]`. This command finds those commits, blames `HEAD` to
count only the lines that actually **survived** to today, and reports which
sensitive surfaces they landed on.

Recognised today: Claude Code, GitHub Copilot, Cursor, OpenAI Codex, Gemini CLI,
Aider, Devin, Windsurf, Sourcegraph Cody, Google Jules, Amp, Continue, Cline.

## What it will not claim

This matters more than the feature list, because a provenance tool that overstates
what it knows is worse than none.

- **Unattributed is not "human-written."** Lines with no AI signal are reported as
  carrying no AI signal. That is all it means.
- **A low percentage can be a floor.** If AI tooling is configured in the repo (a
  `CLAUDE.md`, `.cursorrules`, `.claude/` — tracked *or* gitignored) but few
  commits declare it, the headline renders as `≥N%` and says so explicitly. A repo
  an agent largely wrote must not scan as a reassuring "1% AI" in silence.
- **Some things are gone forever.** A retroactive read cannot recover the prompt,
  the model's reasoning, whether the edit was accepted or rejected, or any review
  state. The output names these every time.

## Commands

```bash
# Start here — nothing to set up
lineagelens scan .                    # what AI code is already in this repo?
lineagelens scan . --category auth    # ...and which of it touches auth
lineagelens scan . --md               # paste-ready inventory for a PR
lineagelens --json scan .             # full machine-readable result

lineagelens scan . --since "6 months ago"
lineagelens scan . --tool "Claude Code"
```

Once capture is running (via the VS Code extension or the proxy), records carry
prompts and models, and two more commands become useful:

```bash
lineagelens blame src/auth.py -i captures.json   # which AI wrote each line
lineagelens report . -i captures.json            # per-file attribution
```

If you self-host the Plus or Max backend, this CLI also manages it
(`start`, `stop`, `status`, `logs`, `backup`, `upgrade`, `rollback`). Those
commands need Docker; the reporting commands above never do.

Run `lineagelens --help` for the full list.

## Capturing what a scan cannot

To record the prompt, model, and accepted/rejected status of AI edits going
forward, install the editor extension — zero configuration, works offline:

```bash
code --install-extension karnatipraveen.lineagelens-base
```

Works in VS Code, Cursor, and Windsurf.

## Requirements

- Node.js ≥ 18.17
- `git` on `PATH`
- A git repository with at least one commit
