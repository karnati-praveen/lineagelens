# LineageLens

Provenance tracking for AI-generated code. LineageLens records which AI tool wrote a
piece of code, with what prompt, using which model, in which file, and whether the edit
was accepted — then stores that record in infrastructure you control.

Self-hosted. MIT licensed. No prompts leave your network.

[![License: MIT](https://img.shields.io/badge/license-MIT-green)](./LICENSE)

## What it does

`git blame` tells you which *person* last touched a line. It cannot tell you that the
line was generated by Claude Code from the prompt "add rate limiting to /api/login", or
that it was produced by Cursor and then accepted unchanged. LineageLens captures that
missing layer — the origin and intent of AI-assisted code — at the moment of generation.

There are two capture paths, used independently or together:

- **VS Code / Cursor / Windsurf extension** — a file watcher that records every AI code
  insertion (file, language, inserted lines, confidence). Works offline with no backend.
- **Universal LLM proxy** — sits between your AI CLI/IDE and the provider API
  (Anthropic, OpenAI, Gemini). It parses each provider's native tool-calling protocol to
  capture the full prompt, the model name, and the accepted/rejected status of each edit.

Captured records flow into a self-hosted FastAPI backend (SQLite or PostgreSQL, optionally
Neo4j) where they can be searched, explained, scored for risk, audited, and exported.

```
Without LineageLens:  "Claude wrote some of it, I think?"
With LineageLens:     prompt="add rate limiting…" model=claude-opus-4-5 file=auth.py status=applied risk=HIGH
```

## Operating modes

| Mode | Who it's for | Storage | Captures prompt + model | Start command |
|---|---|---|---|---|
| **Easy (Base)** | Anyone — zero setup, local or backend-synced | VS Code global state / backend | No — file + lines only | `code --install-extension karnatipraveen.lineagelens-base` |
| **Power (Lite)** | Solo dev or team ≤ 10, single box | SQLite + Docker | Yes | macOS/Linux: `bash lineagelens-scripts/quickstart-lite.sh` · Windows: `.\lineagelens-scripts\quickstart-lite.ps1` |
| **Power (Plus)** | Teams 10–100, governance + CI gate | PostgreSQL | Yes | macOS/Linux: `bash lineagelens-scripts/quickstart-plus.sh` · Windows: see PS1 |
| **Power (Max)** | Compliance, graph lineage, SSO | PostgreSQL + Neo4j + pgvector | Yes | macOS/Linux: `bash lineagelens-scripts/quickstart-max.sh` · Windows: see PS1 |

The full tier capability matrix is the single source of truth in
[`lineagelens-config/tiers.json`](lineagelens-config/tiers.json).

> **Easy vs Power is a capture path, not a tier.** "Easy" means *capturing without the proxy*
> (file + lines only); "Power" means *the proxy is running* (full prompt + model). The tier
> (Base / Lite / Plus / Max) describes the backend. The two are orthogonal: the Base extension
> in Easy Mode can sync file-level captures into a Plus or Max backend (set
> `lineagelensBase.backendUrl`), arriving as `file_diff` records at confidence ~0.35. Plus and
> Max are built for Power Mode, though — running the proxy is what delivers their full value.

### Easy Mode — zero setup

```bash
code --install-extension karnatipraveen.lineagelens-base
```

The extension activates the moment it installs — no configuration, no backend, no API key.
It works in **VS Code**, **Cursor**, and **Windsurf**. The status bar shows
`LL: Easy (local)` and captures are stored in VS Code global state. Use any AI coding tool;
insertions of 4+ lines appear in the LineageLens sidebar automatically.

Optionally, point the extension at a running backend to sync file-level captures without
the proxy: set `lineagelensBase.backendUrl` and `lineagelensBase.ingestToken` in settings.

### Power Mode — full prompt + model capture

Power Mode adds the proxy alongside the extension:

**macOS / Linux:**
```bash
git clone https://github.com/karnati-praveen/lineagelens
cd lineagelens
bash lineagelens-scripts/quickstart-lite.sh
```

**Windows (PowerShell 5.1+):**
```powershell
git clone https://github.com/karnati-praveen/lineagelens
cd lineagelens
.\lineagelens-scripts\quickstart-lite.ps1
```

> Git Bash / WSL users on Windows can also use the bash command above.

Open `http://localhost:8787/setup`, create an admin, then point your AI tools at the proxy:

```bash
export ANTHROPIC_BASE_URL=http://localhost:8788   # Claude Code / claude CLI
export OPENAI_BASE_URL=http://localhost:8788       # Codex CLI / Goose
```

The extension polls `/proxy-health` every 30 s, detects the proxy, and switches the status
bar to `LL: Power` with no restart. Open `http://localhost:8787/dashboard` for full lineage.

## What gets captured

| Field | Example |
|---|---|
| Prompt | `"add rate limiting to /api/login"` |
| Model | `claude-opus-4-5` |
| Tool | Claude Code |
| File | `src/routes/auth.py` |
| Lines | `+47 / -3` |
| Status | `applied` / `rejected` / `errored` |
| Risk score | `HIGH` (auth + network pattern) |
| Confidence | `very_high` (0.92) — five-signal evidence score |
| Timestamp | `2026-05-29T14:22:11Z` |

The proxy parses each provider's native tool-calling protocol — Anthropic `tool_use`
blocks, OpenAI Responses API `function_call` items with the `apply_patch` DSL, and Gemini
`functionCall` parts — and correlates each edit with the next turn's `tool_result` to
resolve whether the edit actually landed.

## Key capabilities

- **Five-signal confidence engine** — every record is scored 0.0–1.0 across capture layer,
  request-UUID correlation, time correlation, content similarity, and tool fingerprint. The
  full breakdown is stored alongside the record.
- **Dynamic model routing** — the proxy classifies each request (simple / standard / complex)
  and can downgrade it to a cheaper model per a per-workspace policy, recording the estimated
  cost savings on every routed record.
- **Tamper-evident hash chain** — on Plus/Max, each record is SHA-256 hashed and linked to its
  predecessor. `GET /integrity/verify` walks the chain and reports the first tampered record.
  This is *tamper-evident*, not immutable: it detects edits that don't also rewrite the chain.
  A party with full write access to the database could recompute every hash; strengthen this
  with externally-witnessed periodic roots if that is in your threat model. Redaction and
  deletion are handled as signed lifecycle tombstones, so the verifier reports
  `validly_redacted` / `validly_deleted` rather than a false `tampered`.
- **Signed AI Bill of Materials** — `POST /integrity/aibom` produces a dual-signed summary
  (percent AI-authored, per-model breakdown, disclosure coverage, chain status). It carries an
  HMAC signature (verifiable by the secret holder) **and** an Ed25519 signature plus public key,
  so a standalone tool can verify the document offline.
- **Agent Trace interchange** — export/import records in the portable
  [cursor/agent-trace 0.1.0](https://github.com/cursor/agent-trace) format
  (`GET /export/agent-trace`, `POST /import/agent-trace`, or the extension's
  *Export Agent Trace* command in Easy Mode).
- **MCP server** — query provenance from Claude Code, Cursor, or any MCP client without
  leaving the chat (Plus/Max).
- **Risk scoring** — heuristic scoring of every insertion by inserted-code patterns
  (credentials, `eval`, shell exec, raw SQL, unsafe DOM) and sensitive file paths.
- **Governance** — RBAC, audit log, review queue, retention/redaction policies, webhooks,
  GitHub Actions risk gate, field-level encryption of secrets, OIDC/SSO (Max).

## Architecture

```
                ┌─────────────────────┐
                │  Your AI tool       │  (Claude Code, Codex CLI,
                │  (CLI or editor)    │   Gemini CLI, Cursor, etc.)
                └──────────┬──────────┘
                           │
        proxy path ◄───────┴───────► extension path
                │                        │
   ┌────────────▼────────────┐  ┌────────▼─────────┐
   │  LineageLens proxy      │  │  VS Code         │
   │  (parses tool_use /     │  │  extension       │
   │   function_call /       │  │  (file watcher)  │
   │   functionCall)         │  └────────┬─────────┘
   └────────────┬────────────┘           │
                │                        │
                └────────────┬───────────┘
                             │  WS / HTTP POST /ingest
                  ┌──────────▼──────────┐
                  │  LineageLens        │
                  │  backend (FastAPI)  │
                  └──────────┬──────────┘
                             │
            ┌────────────────┼────────────────┐
       ┌────▼────┐    ┌──────▼──────┐    ┌────▼────┐
       │ SQLite  │    │ PostgreSQL  │    │  Neo4j  │
       │ (Lite)  │    │ (Plus/Max)  │    │  (Max)  │
       └─────────┘    └─────────────┘    └─────────┘
```

The proxy forwards requests untouched and watches responses to resolve each edit's final
status. The extension works independently — it watches `onDidChangeTextDocument` for 4+ line
insertions and stores them locally or POSTs them to the backend when configured.

## Compliance context

Frameworks such as the **EU AI Act (e.g. Articles 11, 12, 14)** push organizations to document
which AI model generated code, what governed its generation, and what human review occurred.
LineageLens can supply technical records that support such documentation — captured at the point
of generation, with a tamper-evident hash chain and an exportable signed AI-BOM — without
changing the git workflow.

This is **not a compliance certification**, and it does not by itself make you "EU AI Act
compliant." Whether any specific obligation applies depends on your system, your role
(provider/deployer), the use case, and its risk classification, and the regulation is being
phased in over time. Treat LineageLens as evidence tooling and have qualified counsel determine
applicability for your situation.

## What this isn't

- **Not a SAST scanner.** The risk score is heuristic (file path, language, keyword density,
  known-risky patterns). Pair it with Snyk or Semgrep; it does not replace them.
- **Not certified.** RBAC, SSO, hash-chain integrity, and AI-BOM export exist but have not been
  validated against SOC 2 / ISO 27001 controls. Treat it as developer-governance tooling.
- **Not multi-tenant.** One instance serves one workspace tree. Run separate instances for
  unrelated workspace groups.
- **Cursor agent / Copilot CLI are partially out of scope.** Their traffic routes through
  proprietary backends (`api.cursor.sh`, `api.githubcopilot.com`), so you get editor-level
  capture but not the prompt or model.
